	Project Title:
	Detecting AI-Generated and Humanized Text
	Problem seeking to address: 
	Most modern day students and writers often face a lot of backlash if their writing is considered to use artificial intelligence (AI). Sometimes, students or writers could have written a paragraph completely in their own words, but just because of formatting habits like adding too many comma’s, using perfect grammar, or organizing with bullet points, it can often be associated with the use of AI. In recent years AI sounds a lot closer to how humans speak and write than it did a couple of years ago. It is getting harder to detect if a text was written by an AI or a human. Many major commercial detectors, such as Turnitin, GPTZero, or Undetectable AI, cannot guarantee that their results are 100% accurate. They can only give a rough estimate of the probability a score alone does not show users which measured writing habits influenced the result. This project will focus on making those influences easier to understand. This project will build a model that estimates whether a text resembles human written or AI generated writing while also showing a list of writing habits that raised or lowered that score.






	Project Aim: 
	The main aim for this project is to build and test a machine learning model that can identify whether a text was written by a human or generated by Artificial intelligence (AI), while also showing which measured writing habits raised or lowered the model's score.
	Project Scope: 
	In this project, we are not trying to compete with commercial, enterprise-grade detectors. Neither can we guarantee 100% certainty regarding the results. Research shows that it is not reliably possible to guarantee if a text was generated by AI or a human (Sadasivan et al., 2023). The scope of this project is kept practical and simple. We are using the publicly available DAIGT-V2 dataset (Kleczek, 2023) from Kaggle, which contains 44,868 English essays. 27,371 are human-written and 17,497 are generated by different AI models such as ChatGPT, GPT-4, Claude, Llama, Mistral, Falcon and PaLM and my model will only be trained on the output of the AI models listed above as for the human written essays we only have samples of school written examples so the model is limited to student writing. The project will focus on essays of about 300 to 500 words and will not analyse any language other than English. For this project I will force users to input more than 50 words when wanting to scan text. It's added as a safety feature since writing habits are measured more reliably on larger samples. To achieve the scope for this project I will write a feature extracting code which will try and count the following 7 writing habits: average word length, commas per 100 words, Transition words per 100 words, variation in sentence length, average sentence length, semicolons and colons per 100 words, and exclamation and question marks per 100 words. When looking at the data samples of human and AI written text I found these seven writing habits to be a good way to differentiate between AI and human writing. Once my feature extracting code has scanned and measured all the 7 instances we then feed the numbers into a Random Forest classifier which then analyzes the patterns and learns to detect them and make predictions. It works with tabular data that uses less compute. Furthermore, to explain why a text was flagged, the project will incorporate the pre-built SHAP Python library (Lundberg and Lee, 2017), A user will paste their text into a basic web page. The page will show a model score as a percentage and a list of writing habits that raised or lowered that score. The score is an estimate of how similar the input writing style is to the AI examples. It is not a guarantee or 100% reliable as that is simply not possible but because of SHAP we can explain the model's results.
	Project objectives:
	1. To build this application first, I will use the pandas library to load the entire 44,868 English essays present inside of the DAIGT-V2 Kaggle data set into python. Then I will write a Python script to calculate the seven writing measurements listed in the Project Scope.
2. I will split the data using the 80/20 rule 80% for training and 20% remains hidden. By keeping some topics unseen for the final test we can judge how accurate our models' findings were. A Random Forest model will be used for the training. 
3. I will connect the trained model and the SHAP Python library with a basic web page, built with Flask (a Python web tool), HTML, CSS, and JavaScript. On this page, a user can paste text and not only see a model score as a percentage, but also get a clear list of the writing measurements that raised or lowered that score.

Brief overview of relevant literature and datasets: 
	Data set: This project will utilize the DAIGT-V2 data set that is publicly available, as well as hosted on Kaggle. The resource is incredibly useful because it already gives us a massive collection of 44,868 English written essays, which are divided in between real human student essays and responses generated by various other AI models. Additionally the data is labelled which makes my job easier.
Literature review: Our current literature focuses more on commercial AI detectors since they struggle with reliability and most importantly, transparency. Many times when users input text, they receive black box outputs basic percentages that don't quite clarify or give a rational reason behind its reasoning. Studies such as Sadasivan et al. (2023) demonstrate that AI-generated text cannot be reliably detected with 100% certainty because human and AI writing styles, especially in modern day, overlap heavily. Furthermore, research by Liang et al. (2023) shows that standard AI detectors can often falsely flag human writers just because their grammar sounds formal, or they use phrasing that most non-native English speakers use. For building and comparing the classifiers, this project uses scikit-learn (Pedregosa et al., 2011). SHAP (Lundberg and Lee, 2017) is then used to show which writing measurements pushed each score up or down.

Testing and Evaluation:
	The dataset will be divided into training and testing data using an 80/20 split technique. The model will learn from 80% of the essays and will then be tested on the remaining 20%, which it has never seen before. This allows me to measure how well it performs on new examples. Additionally the model will be evaluated using these four measures: Accuracy, how accurate the model’s scores are. Precision how often AI predictions are correct. Recall how many AI essays are detected. False Positive Rate how often human essays are wrongly flagged as AI. Finally, I will manually test the completed application using both AI-generated and human-written essays to ensure that the predictions and explanations behave as expected.
	Ethical Considerations:
	The main ethical risk is that the tool can wrongly flag a human writer as AI. I will clarify on my web interface about the lack of certainty regarding the results and the tool will show a clear warning that nobody should be penalized based on these results. A study from Liang et al. (2023) found that detectors can be biased against non-native English writers. Additionally I will also show the reasoning behind its results using SHAP. The model is trained mostly on school essays, and it may miss text from AI models it has not been trained on for example Qwen, Gemin, GLM, so it can also give false reassurance. The data comes from a public Kaggle dataset DAIGT-V2. It is publicly available on Kaggle and suitable for academic research use. The essays do not include personal details of the students. The web application will not require login, will not store submitted text in a database.
